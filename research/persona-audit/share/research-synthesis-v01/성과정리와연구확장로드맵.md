## 2026-11-04 실행 결과와 우선순위 갱신

**Claude·GPT-4.1 각 114개, 총 228개 생성 원문과 설명서를 확보했고 특징 비교까지 완료했다.** 아래 11월 1~2일의 미확보·대기 문구는 당시 이력으로 보존하며 현재 상태로 읽지 않는다. 원본 사본과 해시는 `data/team-corpus-20261104/`, 결과는 [228발화 특징 비교 보고서](../team-corpus-v01/특징비교보고서.md)에 있다.

GPT-4.1은 API temperature 0.9로 생성됐고 Claude는 대화 중 시범 2질문의 평가를 본 뒤 나머지 4질문의 1단계를 강화했다. 시범 질문 ID는 확인되지 않았다. 생성기와 생성 방식이 교락되므로 각 생성 방식 안에서 질문별 조건 차이를 우선했다. 새 발화·임베딩·자동 평가 생성은 수행하지 않았다.

PER3−N0 3-gram 반복률 차이는 Claude +26.94%p, GPT-4.1 +8.44%p이고 각 6/6 질문에서 증가했다. 첫 100단어 제한에서도 +19.22/+8.67%p였다. 주 비교의 Holm 보정 p는 각각 .0625다. INC3−N0 MATTR50은 −0.238/+0.058로 반대 방향이었다. 이 결과를 보속형 문자 반복의 공통 반응과 생성 절차별 언어 구현 차이로 정리하며 임상 타당도나 모델 서열로 확대하지 않는다.

다음 단계의 우선 후보는 새 생성을 늘리는 것이 아니라 기존 INC3의 다양성 반대 방향이 기능어 반복·내용어 나열에서 오는지를 고정 규칙 하나로 확인하는 것이다. 원평가표와 국소 참조 구간은 아직 별도 미확보 상태여서 ρ=.89/.61 및 41% 수치는 재검증하지 않았다. 최신 실행 조건은 `config/team-corpus-v01.json`, 체크포인트는 `config/research-checkpoint-v12.json`이다.

## 2026-11-02 실행판: 원자료를 기다리지 않는 연구 설계

이 절은 아래 11월 1일 제안의 우선순위를 수정한다. 기존 실험과 기록은 보존한다. **팀의 114개씩 원자료 확보, 국소 탐지 41% 재검산, 교수 자문은 전체 설계의 시작 조건이 아니다.** 아래 과거 제안의 '원자료 연결 후에만 새 비교 선택' 규칙은 전체 연구가 아니라 그 자료에 의존하는 재분석에만 적용한다. 이 문서는 로드맵이며 새 생성을 실행하거나 비용을 승인한 기록이 아니다.

### 최종 목표와 주 질문

**기존 환자 페르소나가 명시한 언어·행동 설정이 실제 발화에서 무엇을 바꾸는지 정량화하고, 원하는 변화와 비의도적 변화를 구분하여 한 가지 개선안을 미사용 조건에서 시험한다.**

주 질문은 '어느 페르소나가 조현병 환자와 가장 비슷한가'가 아니라, '어느 설정이 어떤 관찰 가능한 특징을 재현하며, 어떤 조건에서는 말투·길이·정보 보고만 바꾸는가'다. 후자의 질문은 지금 가진 자료와 자원으로 답할 수 있다. 실제 환자 재현 정확도나 진단 성능은 별도 임상 자료가 있을 때의 확장 질문이다.

조현병 관련 사고과정이 연구의 관심 영역이지만, 모든 프레임워크가 같은 질환·증상 구현을 목적으로 만들어졌다고 가정하지 않는다. 원저가 다루지 않은 특징은 '실패'가 아니라 '미지원/범위 밖'으로 표시한다.

### 1. 기존 성과를 연구 결과로 통합한다 — 지금 시작

새 모델 호출 없이 기존 특징 목록, 원응답, 수치 결과를 연결한다. 기록마다 원출처, 프롬프트 버전, 실제 백엔드, 사례·질문, 측정값을 구분한다. 이미 확인한 필드 전달 오류·출력 제한은 결과 해석에 반영하되 감사만 반복하지 않는다.

기존 PATIENT-Ψ·PatientSim 특징 목록과 PSYCHE 구현 감사를 재사용한다. 팀 GitHub `yyeonseoo/Tobedoc`의 현재 확인 commit은 `58477f301a5b850b7fe0f8056f18bf9f01a10ea7`이다. 이 저장소의 공개 데이터 분석·교란 점검·증강 보고서는 연구 배경과 방법론적 근거로 사용한다. `data/`, `synthetic/`는 Git에서 제외되어 있어 전체 원자료 재계산은 하지 않았고, 두 모델 각 114개 TLC 실험도 현재 공개 파일에서 찾지 못했다. 저장소의 Claude 112개 증강 기록은 그 실험과 다른 자료다.

**완료 산출물:** 프레임워크별 '의도한 특징 → 관찰 가능한 출력 → 실제 측정 결과' 목록과 기존 결과의 핵심 그림. 여기서부터 실질 결과로 보고한다.

### 2. 사고과정 관련 주 비교 하나를 고정한다 — 원자료 없이 가능

PATIENT-Ψ·PatientSim·PSYCHE의 출처 목록은 유지한다. 조현병 언어 연구와 직접 연결되는 주 비교는 **질문 관련성 및 문장 간 연결의 변화**를 우선한다. 발화량과 정보 보존은 보조 측정이자 혼동 요인이다. 반복·음운 연상 등은 팀 자료 재분석의 확장 항목으로 두고 이번 본 실험 전체를 다섯 유형의 완전 교차로 늘리지 않는다.

PSYCHE 사고과정 설정을 중심 후보로 두되, 원저 방법과 공개 재구현의 차이를 표시한다. PATIENT-Ψ의 tangent와 PatientSim의 dazedness 등은 같은 임상 증상의 동등 구현으로 서열화하지 않고, 서로 다른 지시가 산출하는 언어 변화의 비교 대상으로 쓴다. 공개 구현을 Qwen에 이식한 결과에는 '로컬 적용판'이라는 이름을 붙인다. 특정 프레임워크의 원형 성능과 동일시하지 않는다.

비교는 두 층으로 분리한다. (a) 동일 허구 사례·질문·백엔드에서 공개 지시 모듈을 비교하는 통제 실험, (b) 각 원저 설정 전체를 따르는 시스템 재현. 이번 주 실험은 (a)이며, 실행 자원이 확보되지 않은 (b)는 필수조건이 아니다.

**완료 산출물:** 한 장의 고정 설계서. 대상 지시, 예상 방향, 주 측정값, 정상 대조, 분석 단위, 개발/검증 분리, 종료 조건을 명시한다. 문자열 변화나 단어 수 준수만을 사고과정 구현 성공으로 정의하지 않는다.

### 3. 같은 조건에서 원하는 변화와 부작용을 비교한다

비교 조건은 중립 지시, 단순한 특징 이름 지시, 출처 기반 페르소나 지시로 구성한다. 정상 대조는 주 질문을 직접 혼동시키는 장황하지만 관련된 답변과 자연스러운 여담을 우선한다. 기존 자료에 대응 조건이 있으면 재사용하고, 빠진 조건만 생성한다. 서로 다른 생성기의 정상·목표 자료를 섞어 이진 분류기를 만들지 않는다.

관찰 항목은 질문-답변 관련성, 문장 간 연결, 길이와 요청 사실 보존이다. 같은 사례·질문 안에서 지시만 바뀔 때의 차이를 먼저 계산한다. 임베딩 유사도는 의미적 근접성을 측정하는 후보이지 임상 등급이 아니다. 기존 유사도 실패 사례를 함께 제시하며 임베딩 점수 하나로 페르소나의 임상 품질 총점을 만들지 않는다.

길이가 조작 결과일 수 있으므로 '일단 생성 후 길이를 회귀로 지우기'만 하지 않는다. 실제 배치에서는 목표 길이를 공통으로 둔 조건과 관찰된 길이 차이를 함께 보고한다. 길이 때문에 효과가 생기는지 확인할 때에는 적절한 대응 대조를 사용한다.

**완료 산출물:** 조건별 특징 분포, 사례-질문별 대응 변화, 대표 발화 원문. 핵심 해석은 '어떤 언어 특성이 바뀌었는가'와 '원하는 변화 없이 부작용만 생겼는가'다.

### 4. 실패 원인 하나만 겨냥해 수정한다

예를 들어 증상 이름만으로 원하는 변화가 생기지 않는 경우에는 행동 지시를 구체화하고, 정보 보고와 말투가 섞이는 경우에는 사실 상태와 표현 규칙을 분리한다. 주 질문과 무관한 수치 보존 문제만 개선했다고 사고과정 구현을 개선했다고 부르지 않는다. 이 단계에서 개선 대상은 하나만 선택한다.

수정 전후뿐 아니라 가능하면 비슷한 길이의 비표적 지시를 추가한 대조 또는 해당 지시를 제거한 비교를 둬서, 단순히 프롬프트가 길어진 효과와 구별한다. 목표 특징의 변화와 사실 보존·정상 대조 반응을 함께 본다. 평가값만 잘 나오도록 특정 단어를 유도하는 수정을 피한다.

**완료 산출물:** 원형 적용판·수정판 비교와 개선 원인에 대한 제한된 설명. 개발 자료에서만 좋아졌다면 개선 확정이라고 보고하지 않는다.

### 5. 미사용 사례로 확인하고 결론을 고정한다

검증 전 주 비교, 측정 규칙, 오류 처리와 성공 기준을 고정한다. 허구 인물·사례 단위로 개발과 검증을 분리하고 질문 표현도 바꾼다. seed 반복이나 문장 여러 개를 독립 환자로 세지 않는다. 사례 수가 적으면 효과 분포와 사례별 방향을 중심으로 보고하고, 추정 가능한 경우 사례 군집 단위 구간을 계산한다. 보편적인 임상 임계값이 없는 지표에 임의 합격점을 붙이지 않는다.

다른 생성기 확인은 일반화 주장에 맞춰 추가한다. 로컬 Qwen에서만 시험했다면 그 적용판에 관한 결론으로 완결할 수 있다. 여러 생성기에도 통한다는 주장을 하려면 독립 생성기 확인이 필요하다. 기존 팀 원자료를 받으면 먼저 재분석하며, 대응되지 않는 조건을 검증 자료인 것처럼 합치지 않는다.

**종료 조건:** 한 번 고정한 검증 배치까지 평가하면 결과를 정리한다. 효과 유지, 부작용과의 교환, 비재현 모두 결론이다. 결과를 본 뒤 같은 검증 자료에서 다음 지표·수정안을 반복 탐색하지 않는다.

### 6. 팀 연구와 연결하고 보고서로 마무리한다

114개씩의 원자료가 오면 유형별·생성기별 결과를 재계산하고, 어떤 지표가 어떤 모사 유형에 반응했는지 이번 결과와 연결한다. 41% 국소 탐지는 참조 구간과 우연 기준선을 확인한 뒤 재검증할 후보이지 미리 정한 주성과가 아니다. 원자료가 늦으면 해당 결과는 팀 보고 수준으로 남기고 지금의 주 실험을 먼저 끝낸다.

교수 자문은 대표 발화와 정상 대조의 구별, 임상 개념 대응, 과장된 모사 여부에 집중한다. 표본 자문과 독립 맹검 임상 채점은 구분한다. 자문 일정 때문에 로컬 분석이나 합성 자료의 통제 비교를 멈추지 않는다.

**최종 산출물:** 특징 지도, 통제 비교 그림, 수정 전후 검증 결과, 짧은 원문 예시, 재현 코드·조건표와 한국어 2~3쪽 보고서. 보고서 순서는 '의구심 → 무엇을 어떻게 비교했는가 → 결과 → 의미 → 남은 검증'이다.

### 자원 사용과 즉시 다음 작업

이 로드맵의 제안은 기존 코드와 결과를 우선 사용하는 것이다. 파싱·특징 계산·통계·그림은 로컬 코드, 설계·문헌 해석·결론은 assistant, 애매한 연구 선택은 사용자, 임상 대응은 교수 자문이 맡는다. Ollama는 사용할 경우 고정 백엔드이며 자동 임상 평가자가 아니다. 유료 API·설치·모델 다운로드·원격 작업을 새로 시작하지 않는다.

**즉시 다음 작업은 1단계의 기존 결과 통합과 2단계의 주 비교 고정이다.** 새 생성 수는 기존 대응 조건의 부족분을 확인한 뒤 상한을 정하며, 원자료 연락을 기다리는 동안 기존 32개 보류 요청이나 다른 대규모 배치를 자동 실행하지 않는다. 1·2단계 후에는 재차 준비 단계를 추가하지 않고 정해진 비교 분석으로 넘어간다.

## 지금 확보한 성과와 연구에서의 위치

### 팀의 유형과 중증도 연구

중간보고서에는 Claude와 GPT-4.1에서 각각 114개 발화를 생성했고, 의도한 중증도와 블라인드 LLM 평가 간 Spearman ρ=0.89를 얻었다고 제시되어 있다. 이는 생성 조건과 LLM 평가의 대응에 관한 결과다. 임상 정답과의 일치도나 지표 자체의 타당도와는 별도로 둔다. 유형을 합친 상관인지, 유형별로도 유지되는지, 어떤 모델이 평가했는지 원자료와 조건표에서 확인할 필요가 있다.

중증도 추적과 대조 조건 구분을 모두 통과한 지표가 없었다는 결과는 중요한 연구 성과다. 어떤 현상에는 반응하지만 정상적인 변이와 구별하지 못하는 지표를 확인했다는 뜻으로 발전시킬 수 있다. 유형별 반응을 한 지표의 종합 순위로 덮지 않는다.

국소 구간 겹침 41%, 우연 수준 25%, p=.001은 가장 우선해서 확인할 확장 후보다. 아직 새로운 표본의 확인적 결과는 아니다. 이번 정리에서는 PPT만 근거로 보존했으며, 원자료·참조 구간·우연 모형·선택 절차를 재계산하지 않았다. 숫자가 보고서에 있다는 이유만으로 독립 검증 완료로 격상하지 않는다.

### 페르소나 지시가 실제 출력에 미치는 영향

기존 네 축의 본 과제와 수치 보존 후속 실험에는 총 240개 응답 기록이 남아 있다. 재분석 자료와 같은 문자열의 반복을 포함하며 독립 환자 수나 고유 발화 수가 아니다. PATIENT-Ψ·PatientSim의 일부 지시를 Qwen으로 옮긴 결과로, 원형 시스템의 임상 성능 비교와도 구분한다.

- **발화량과 정보량 분리:** 단순 장황 지시, PSI 지시, PatientSim 지시의 평균 길이는 약 127.2·238.6·309.7단어였다. 요청 정보 표식은 각각 64/64·62/64·64/64였다. 말이 길어진 정도와 요청 정보가 더 담긴 정도는 달랐다. 분모 64는 응답 수가 아니라 요청 정보 항목 수다.
- **경계적 지시와 질문 순서:** 미사용 허구 기록 2개와 새로운 질문 표현에서 수행한 32응답 비교의 순서 효과 상호작용은 −0.542였다. 단순 간결 대조군과 달리 경계적 지시에서 정보 표식의 식별이 순서에 민감했다. 이는 임상적 경계심의 증명이 아니라, 지시와 질문 구성에 따른 정보 보고 양상의 결과다. 단위 환산을 인정한 사후 점검에서는 −0.500이었다.
- **주제 관련성과 국소 유사도 분리:** 48응답의 plain·verbose·tangent 조건은 모두 요청 항목을 48/48 언급했지만, tangent와 verbose의 인접 코사인 차이는 약 −0.0386이었다. 요청 정보를 전달했다는 것, 질문에 계속 관련되어 있다는 것, 문장끼리 비슷하다는 것은 서로 다른 특성이다.
- **표현 완화와 사실값 보고 분리:** pleasing 지시는 표현뿐 아니라 보고 수치에도 영향을 줬다. 수치 보존 한 문장을 추가한 후에도 세 항목을 모두 보존한 답은 보조 감사에서 PSI 3/8·PatientSim 1/8이었다. 특히 PatientSim의 underreporting 요구를 단순 입력 오류로 취급하지 않는다. 표현 방침과 보고 내용이 어떻게 결합되는지 보여 주는 결과로 보존한다. 기존 수치 파서의 오류와 사후 보조 분석도 별도로 남긴다.

이 갈래를 단순 부록으로 모두 밀어낼 필요는 없다. **사고장애를 지시하지 않아도 페르소나와 면담 조건이 측정값을 바꿀 수 있는지** 확인하는 대조 실험의 근거가 된다. 단, 위에서 조작한 것은 지시 모듈이며 임상 증상 자체가 아니다.

### 측정 도구에 관한 성과

기존 48응답에서 다른 주제 문장을 넣은 조건과 요청 주제 문장을 넣은 조건을 비교했을 때, 인접 코사인은 20/48에서 다른 주제 삽입 쪽이 더 높았다. 따라서 높은 유사도를 곧 좋은 연결성으로 읽을 수 없다. 이것은 통제된 측정 점검이며 새로운 환자 연구가 아니다.

일반 뉴스 요약 외부 자료에서는 적격 1542개, 원문 기사 100개, 생성 시스템 16개를 분석했다. 현재 OS 임베딩의 인접 코사인과 전문가 연결성 평가 간 상관은 ρ=0.0317, 기사 군집 부트스트랩 95% 구간은 약 −0.039~0.100이었다. 이 결과는 해당 임베딩·자료·전처리에서 지표 채택을 지지하지 않았다는 근거다. 모든 의미 유사도 지표가 무효라는 주장으로 넓히지 않는다. 문장 경계의 사후 수정 이력과 제외된 58개도 보존한다.

이 결과들은 팀의 지표 탐색을 중단시킬 이유가 아니라, **지표가 어떤 조건에서 오해를 유발하는지 함께 시험해야 한다는 근거**다. 실패한 지표를 다른 이름의 임상 점수로 재포장하지 않는다.

### 구현 점검과 PSYCHE 전환에서 남길 것

자동사고 필드의 undefined 전달, 문장 수 상한의 편중, 공개 재구현과 원저 방법의 차이, PSYCHE의 12개 Behavior 필드와 Roleplay-doh 공개 주제 7개에 대한 출처 목록은 재현성과 입력 타당도를 위한 자산이다. 두 특징 목록을 19개 동등한 임상 항목으로 합치지는 않는다. 제한된 Roleplay-doh 개별 전문가 원칙의 미확보도 팀 연구 전체를 막는 조건으로 만들지 않는다.

PSYCHE 로컬 길이 제어 실험은 32응답 중 신규 28개·재사용 4개였다. 숫자 목표 준수는 간단한 지시 6/8, MFC 내부 지시 7/8, 시스템 끝 지시 4/8이었다. 이는 길이를 요청하는 방식의 공학적 결과다. 7/8이라는 관찰만으로 후속 자료의 길이가 완전히 통제되었다고 선언하지 않는다.

사고과정 개발 실험 16개도 보존한다. 두 지시 방식 모두 Normal/Derailment 대응쌍의 동일 출력은 0/4였으므로, 문자열 변화만으로 개선을 구별할 수 없었다. 사전 길이 민감도 조건에 든 비교는 각각 2/4·3/4였다. 미생성 검증 요청 32개는 그대로 남겨 두되, 팀의 새 평가 질문에 도움이 되는지 확인하지 않은 채 자동 실행하지 않는다.

## 전면 수정한 실행 순서

### 첫 번째 결과물은 기존 자료의 공통 분석이다

중간보고서 5~8장의 원문·생성 조건·평가 모델·NLP 측정값·참조 구간을 연결한다. 이것은 새 실험을 위한 끝없는 준비가 아니라, 기존 결과를 재현하고 유형별 그림을 완성하는 작업이다. 새 생성은 하지 않는다.

기록 단위에는 사례, 질문, 생성 모델과 버전, 유형, 의도 중증도, 대조 조건, 원응답, 평가 모델, 평가값, 구간 근거의 출처를 둔다. 의도 중증도·LLM 평가·전문가 관찰을 같은 정답 열에 합치지 않는다. 같은 인물과 질문의 반복, 생성기별 대응 관계와 누락 조건을 구분한다.

완료 기준은 유형별·생성 모델별 지표 반응 그림, 대조 조건의 분포, 재현된 수치와 재현되지 않은 수치 목록이다. 이 단계에서 이미 보고서에 들어갈 결과를 만든다. 원자료가 없는 항목만 보류하고, 근거가 있는 다른 분석까지 멈추지 않는다.

### 두 번째 결과물은 혼동 요인의 지도다

기존 페르소나 실험에서 확인한 길이, 정보 공개, benign한 주제 변화, 수치 보고 정책을 지표의 대조 조건으로 연결한다. 모든 축을 다시 완전 교차해 거대한 새 실험을 만들지는 않는다. 주지표를 가장 크게 혼동시키는 대조부터 우선한다.

같은 생성기와 동일 사례·질문 안에서 비교 가능한 조건을 먼저 분석한다. Qwen의 정상 스타일 자료와 Claude/GPT의 사고장애 모사 자료를 그대로 합쳐 양성·음성 분류를 만들면 생성기 차이를 배우는 문제가 생길 수 있다. 기존 서로 다른 자료는 먼저 별도 스트레스 테스트로 사용한다.

완료 기준은 각 지표가 목표 유형과 대조 변화 중 무엇에 반응하는지 보여 주는 반응 지도다. 정상적 화제 전환에도 크게 반응하면 임상 특이성이 확보됐다고 표현하지 않는다. 가능한 범위에서 길이 조작에 대한 총 반응과, 길이를 맞추려 한 설계의 결과를 함께 제시한다. 길이가 지시의 결과일 수 있으므로 사후 길이 보정 회귀 하나로 모든 혼동이 제거됐다고 보지 않는다.

### 세 번째 결과물은 국소 탐지의 재현 가능한 검증이다

우선 41% 결과의 참조 구간이 누가 어떤 근거로 정한 것인지 확인한다. 기계적으로 삽입한 문장 위치, 생성 지시가 지정한 위치, LLM이 다시 추정한 위치, 전문가가 관찰한 위치는 서로 다른 근거다. 이를 임상 정답 구간으로 통일하지 않는다.

같은 자료에서 전체 평균, 사전 고정한 국소 구간 방법, 길이와 선택 기회를 맞춘 무작위 기준선을 비교한다. 구간 수·길이·탐색 횟수가 다르면 25%라는 기준선을 그대로 가져오지 않는다. 창 길이나 임계값을 여러 번 고른 뒤 가장 유리한 p값만 보고하지 않는다.

위치 맞히기와 유형 구분도 나눈다. 단순히 질문에서 멀어진 부분을 잘 찾는 방법이 자연스러운 여담까지 모두 이상으로 표시하는지 함께 본다. 탈선과 질문 부적합성을 하나의 현상으로 취급하지 않는다. 다른 유형에 음운·반복·문장 내부 특성이 필요하면 해당 측정 가족을 유지하되, 한 논문에서 다섯 유형 모두의 성공을 필수 목표로 걸지 않는다.

완료 기준은 재현된 효과, 불확실성, 우연 기준선과의 차이, 대조 조건에서의 오탐 양상이다. 새로운 대규모 LLM 채점이 이 단계의 기본 전제는 아니다.

### 네 번째 결과물은 미사용 조건에서의 확인이다

개발 결과를 본 뒤 주지표·구간 선택 규칙·대조 조건·주 비교를 한 번 고정한다. 사례 단위로 분리한 미사용 자료와 독립 생성기 조건에서 같은 방법을 적용한다. 미사용 자료는 결과를 보며 규칙을 고치는 용도로 쓰지 않는다.

분석 단위는 응답 수만이 아니라 사례·질문 묶음이다. 반복 seed나 한 답변의 여러 문장을 독립 환자로 세지 않는다. 사례 수가 충분할 때 사례 단위 불확실성 추정을 사용하고, 적으면 그 범위에서 기술 결과로 보고한다. 유형을 합친 상관만으로 성공을 판단하지 않는다.

새 생성이 꼭 필요한 비교가 남은 경우에만 부족한 조건을 명시하고 한 번의 제한된 확인 배치를 설계한다. 현재 숫자만으로 표본 수나 검정력을 정한 척하지 않는다. 기존 결과의 분산·사례 수와 사용 가능한 자원을 본 뒤 정하며, 이번 로드맵은 자동 생성 허가가 아니다.

### 다섯 번째는 실패 하나를 고치는 선택 과제다

지표가 국소 이상을 놓치는 문제라면 국소 방법을 개선한다. 생성 지시가 원래 의도와 다른 현상을 만드는 문제라면 지시를 바꾼다. 상태 정보와 보고 전략이 섞이는 문제라면 둘을 분리한 구조를 시험한다. 여러 문제를 동시에 고친 뒤 무엇이 효과였는지 모르게 만들지 않는다.

개선이 필요한 구체적 실패와 평가 가능한 결과가 없으면 이 단계를 생략한다. 단어 수가 잘 맞았다는 이유만으로 사고장애 모사가 개선됐다고 보고하지 않는다. 개선안이 미사용 조건에서 효과가 없으면 그 결과를 남기고 반복적으로 새 지표를 찾지 않는다.

### 임상 자문은 병행하되 전체 작업의 문지기로 두지 않는다

자문이 가능하면 대표 원문과 혼동 사례를 가져가 표적 현상과 평가 준거를 검토한다. 자문 한 번, 제한된 표본 관찰, 전체 독립 채점과 평가자 일치도 연구는 서로 구분한다.

자문을 확보하지 못해도 기존 데이터 재분석, 정상 대조 비교, 독립 생성 모델과 미사용 사례 검증은 진행한다. 그때 최종 주장은 합성 언어에서의 측정 특성으로 한정한다. 임상적으로 검증된 사고장애 탐지기, 실제 환자의 재현 정확도, 임상 평가자 대체라는 주장은 하지 않는다.

## 성공과 종료 조건

- 국소 방법이 독립 조건에서도 더 유용하고 대조 조건을 구별한다면, 해당 현상과 조건에 한정한 측정 개선을 주결과로 삼는다.
- 국소 효과가 재현되지 않거나 정상 변화와 구별되지 않으면, 탐색 결과의 비재현 또는 지표의 불충분한 특이성을 결론으로 삼는다. 실패를 숨기거나 같은 검증 자료에서 다음 지표를 계속 찾지 않는다.
- 페르소나의 보고 정책 효과만 안정적이라면 그 결과는 별도 행동 감사 성과로 남긴다. 조현병에 특이적인 현상으로 승격하지 않는다.
- 임상 자문이 없으면 주장 범위를 좁혀 연구를 마무리한다. 모든 결과를 준비 작업이라고 부르며 종료를 미루지 않는다.

최종 산출물은 출처와 실제 행동을 연결한 특징 목록, 유형별 지표 반응과 대조 조건 분석, 국소 탐지의 확인 또는 비재현 결과, 재현 가능한 원문·코드·조건표, 2~3쪽 한국어 요약이다. 한 본문에 모든 실험을 같은 비중으로 넣지 않고, 측정 연구의 주결과와 페르소나 행동 감사의 보조 결과를 구분한다.
